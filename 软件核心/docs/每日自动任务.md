# 每日自动任务

入口：批量混剪 → 公共素材配置旁的“每日自动任务”。

## 首次配置

1. 先保存各模板的素材目录、混剪模式、字幕、水印和核心参数。
2. 填写产品或计划名称，勾选需要参与的模板。
3. 填写每店每日目标，例如 800。A店选两个模板、B店也选两个模板时，每个模板各分配约400，两个店合计约1600；不是四个模板共分800，也不是每个模板各生成800。
4. 为需要轮换钩子的模板填写钩子总目录。软件从其直接子文件夹中每天选择一批，批内支持递归读取。
5. 设置每日开始时间，勾选每天自动执行，点击“创建计划”。计划会显示并选中在左侧“已保存计划”列表中。
6. 修改已有计划后点击“保存修改”；“另建计划”用于切换到空白表单。清空、切换计划或关闭窗口前，未保存内容会弹出提醒。立即执行今日计划可跳过当天的开始时间限制。

钩子总目录留空时沿用模板原来的钩子目录；AI开场模式不使用钩子。修改模板需通过原来的“保存当前”保存，已经建立的任务不会随之改变。

## 数量与素材

- 按模板中保存的店铺名称分组，每店独立均分目标；店内余数依勾选列表顺序分配。店铺名称前后空格忽略，缺少店铺名称需先补齐。计划名称仅作备注，不决定店铺归属。
- 界面显示每个模板的目标、各店分配及整个计划的合计目标。未勾选模板不参与。
- 旧计划中保存的数量沿用，但解释为每店目标，后续新任务采用新规则。已经建立的队列任务、断点、当日去重记录保持原样，不会当天重复建立或追加数量。
- 传统音频及普通拼接按音频目录全部有效音频计数；数字人模式按第一轨道全部有效视频计数。
- 分配目标再换算成最接近的整数轮数，因此实际预计总数可能略高或略低。5条音频对应800条时为160轮；6条为133轮、798条。
- 不沿用旧的手动勾选列表。新增文件会在每日任务准备时重新纳入；无效驱动素材会跳过并记录原因，无有效驱动素材时等待修复后重试。
- 共用同一钩子总目录的模板，当天优先分配不同的有效子目录；同一软件内的不同计划也共享当天使用记录。
- 有效子目录不足时才复用，并优先选择当天分配次数少的目录。例如4个模板、2个有效子目录，尽量每个目录分配2次。
- 当天分配次数相同时，未使用批次优先，其次是最久未使用批次；不同总目录的同名子目录互不影响。
- 使用记录仍按计划和模板保存，兼容旧版记录；只有整批成功入队才持久化。重启、重试和断点续做沿用已入队快照，不重新抽取。
- 本规则只用于每日计划中填写了钩子总目录的模板，不改变手动混剪的素材选择。AI开场不使用也不占用钩子批次。
- 文件为空或最近10秒内改动的文件暂不纳入。网络不可访问不当成空目录；准备失败5分钟后重试。
- 界面空闲时每2分钟后台检查目录变化，支持深层子目录。剪辑中不重排素材表，避免干扰音频进度和任务断点。

## 队列与归档

- 同一计划、同一天最多自动建立一次。任务与当天记录原子提交；清除已完成队列后仍不会当天重复生产。
- 输出为：原保存目录/店铺/生产日期/产品_模板编号_计划编号。跨午夜仍沿用该任务的生产日期。
- 软件重新打开后可继续未完成的每日等待任务。手动暂停队列或停止任务，也会暂停每日自动调度；在计划窗口恢复。
- 当前运行任务和已有等待任务优先，不抢占执行，也不自动补建软件关闭期间所有漏掉的日期。
- 多个计划同时到期时，优先执行从未生产或最久未生产的计划，避免某个产品跨天后反复抢先。
- 发现手动等待任务时不擅自启动它们，需手动处理或启动等待队列。
- 失败、停止的任务保留在任务队列中供检查及重试，不重新建立同日批次。历史裁减只移除超过200条的已完成记录，不移除未完成任务。
- 软件与电脑需要保持运行；本功能不负责系统唤醒或开机自启，也不会提高单条视频的实际渲染速度。

## 修改范围与验证

- services/daily_production_service.py：数量分配、递归扫描、驱动验证、钩子轮换、模板任务快照。
- modules/batch_mixer/daily_plan_dialog.py：小型计划设置窗口。
- modules/batch_mixer/daily_automation_mixin.py：后台准备、定时调度、自动刷新和生命周期。
- services/batch_project_service.py：计划、去重记录与队列统一持久化，保留未完成任务。
- modules/batch_mixer/project_queue_mixin.py：入口、暂停/关闭衔接、保存字幕样式参数。
- tests/test_daily_production.py：分配、模式、目录、轮换、去重、真实音频探针、线程衔接及主窗口入口测试。

不修改FFmpeg剪辑、ROI计算及渲染算法。涉及新模块及主窗口入口，客户必须使用重新打包的累计覆盖包；网盘资源包不用因此重新下载。正式长时间无人值守前应先用较小目标数量跑通自己的目录与模板。
